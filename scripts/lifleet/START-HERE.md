# START HERE — lifleet

Покрокова інструкція. Кожен крок — конкретна команда або конкретна дія.
Всі команди виконуються з папки проєкту: `scripts/lifleet/`.

---

## 1. Реєстрація і ключі

1. Зареєструйся на https://www.browserbase.com (звичайний email, безкоштовний план).
2. У дашборді відкрий **Settings → API Keys** — там лежать:
   - **API Key** → це `BROWSERBASE_API_KEY` (починається з `bb_live_...`)
   - **Project ID** → це `BROWSERBASE_PROJECT_ID` (UUID; також видно в **Settings → Project**)
3. Більше нічого в дашборді налаштовувати не треба.

## 2. Встановлення

```bash
cd scripts/lifleet
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pip install -e .
playwright install chromium
```

Перевірка, що все зібралось (мережа не потрібна):

```bash
pytest -q
lifleet --help
```

## 3. Куди покласти ключі

Створи `.env` з прикладу:

```bash
cp .env.example .env
```

Відкрий `.env` і встав свої значення `BROWSERBASE_API_KEY` і `BROWSERBASE_PROJECT_ID`.
Файл уже в `.gitignore` — у git він не потрапить.

**Варіант А — з 1Password (ключі не лежать у shell-історії та `.bashrc`):**
у `.env` замість значень поклади op://-посилання (`BROWSERBASE_API_KEY=op://Private/Browserbase/api-key`) і запускай кожну команду через:

```bash
op run --env-file .env -- lifleet check --all
```

**Варіант Б — простий, без 1Password:** перед роботою в поточній сесії терміналу:

```bash
set -a; source .env; set +a
```

Після закриття терміналу ключі зникають з оточення. У `.bashrc`/`.zshrc` їх не додавай.

## 4. Додай п'ятьох авторів

Заміни імена на реальні. `--country` — країна, з якої «ходить» браузер автора (проксі):

```bash
lifleet add alex   --name "Ім'я Прізвище 1" --country UA
lifleet add maria  --name "Ім'я Прізвище 2" --country UA
lifleet add ivan   --name "Ім'я Прізвище 3" --country UA
lifleet add olena  --name "Ім'я Прізвище 4" --country UA
lifleet add petro  --name "Ім'я Прізвище 5" --country UA
lifleet list
```

## 5. Invite: як проходить логін автора

Для кожного автора, по одному (безкоштовний план = 1 сесія одночасно):

```bash
lifleet invite alex
```

Що відбувається і що робиш ти:

1. Команда створює хмарний профіль (context) і друкує **посилання** у великому блоці.
2. Скопіюй посилання і надішли автору (текст повідомлення — крок 6).
3. **Не відкривай посилання сам, поки автор працює** — це один спільний екран браузера: два курсори заважатимуть одне одному, а головне — ти побачиш, як людина вводить пароль.
4. Чекай. Автор логіниться, проходить 2FA, бачить свою стрічку і відписує тобі «готово».
5. Повертаєшся в термінал і тиснеш **Enter**. Скрипт сам перевірить сесію і надрукує
   `OK alex: live, профіль: <ім'я з LinkedIn>` — звір, що ім'я збігається з автором.
6. Якщо автор не встиг за 20 хвилин — перервалось? Просто запусти `lifleet invite alex` ще раз і надішли новий лінк. Довший лінк: `lifleet invite alex --minutes 40`.

## 5b. Альтернатива invite: import куків (обхід капчі на free plan)

На безкоштовному плані немає проксі, і LinkedIn часто ганяє нескінченну капчу
на датацентр-IP — інтерактивний `invite` не проходить. Обхід: автор логіниться
**у себе на комп'ютері** (де капчі немає) і надсилає тобі свої куки LinkedIn.
Пароль при цьому не передається.

Що робить автор (інструкція для нього — нижче, у кроці 6b):
1. Ставить розширення **Cookie-Editor** (Chrome Web Store / Firefox Add-ons).
2. Відкриває залогінений `linkedin.com`.
3. Тисне іконку Cookie-Editor → **Export** (унизу) → **Export as JSON**
   (копіює в буфер) → вставляє у файл і надсилає тобі, АБО одразу Export до файлу.

Ти зберігаєш присланий файл, наприклад `~/Downloads/oleksandr.json`, і заливаєш:

```bash
lifleet import oleksandr ~/Downloads/oleksandr.json
```

Скрипт кладе куки в профіль (context) автора, перевіряє сесію і друкує
`OK oleksandr: live, профіль: <ім'я>`. Далі все як завжди — `check`, щоденні прогони.

**Чесний мінус**: щоденні сесії на free plan усе одно йдуть з датацентр-IP, тому
LinkedIn може розлогінити акаунт за кілька днів (тоді просто повтори import зі
свіжим експортом) або показати challenge. Стабільно — тільки з проксі (платний план).

## 6. Готовий текст повідомлення автору

Скопіюй, встав лінк і надішли:

> Привіт! Налаштовую систему, яка допомагатиме нам з LinkedIn. Щоб вона працювала від твого імені, треба **один раз** залогінитись у захищеному браузері в хмарі.
>
> Ось посилання: `<ЛІНК>`
>
> Що зробити:
> 1. Відкрий посилання — побачиш вікно браузера зі сторінкою входу LinkedIn.
> 2. Введи свій логін і пароль як звичайно. Прийде код підтвердження (2FA) — введи і його.
> 3. Дочекайся, поки завантажиться твоя стрічка.
> 4. Відпиши мені сюди одним словом: «готово».
>
> Важливо:
> - Посилання живе **20 хвилин**. Не встиг(-ла) — попроси нове, це секунда.
> - Запис екрана в цій сесії **вимкнено**: ніхто не бачить і не зберігає те, що ти вводиш. Пароль знаєш тільки ти, мені він не потрібен і ніде не зберігається.

## 6b. Текст автору для варіанту з куками

> Привіт! Щоб система працювала від твого імені, треба один раз передати мені
> «перепустку» твоєї LinkedIn-сесії (не пароль!). Зроби так:
>
> 1. Встанови розширення **Cookie-Editor**:
>    - Chrome: https://chromewebstore.google.com/ (пошук «Cookie-Editor»)
>    - Firefox: https://addons.mozilla.org/ (пошук «Cookie-Editor»)
> 2. Зайди на **linkedin.com** і переконайся, що ти залогінений (бачиш свою стрічку).
> 3. Натисни іконку Cookie-Editor у панелі браузера.
> 4. Внизу вікна натисни **Export** → обери **Export as JSON**.
> 5. Надішли мені отриманий файл (або встав текст сюди).
>
> Це не пароль і не дає доступу до пошти чи зміни пароля — лише поточний вхід у
> LinkedIn. Якщо колись передумаєш — просто зміни пароль у LinkedIn, і «перепустка»
> одразу перестане діяти.

## 7. Перевірка живості та cron

Разова перевірка всіх:

```bash
lifleet check --all
```

Друкує таблицю (slug / status / identity / last_ok) і повертає **exit 1**, якщо хоч хтось не `live` — тому в cron пінг прилітає лише коли щось зламалось. Приклад: щодня о 9:00 з нотифікацією через ntfy.sh (заміни `ШЛЯХ` і `mytopic`):

```bash
crontab -e
```

```
0 9 * * * cd ШЛЯХ/scripts/lifleet && bash -c 'set -a; source .env; set +a; ./.venv/bin/python -m lifleet check --all >> check.log 2>&1' || curl -s -d "lifleet: хтось з авторів відвалився, дивись check.log" ntfy.sh/mytopic
```

(Нотифікації на телефон: постав застосунок ntfy і підпишись на свій topic. З 1Password: заміни `bash -c 'set -a; ...'` на `op run --env-file .env -- ./.venv/bin/python -m lifleet check --all`.)

Щоденна робота скриптами — дивись `example_daily.py`: цикл по всіх авторах, пауза 90–240 с між ними, наприкінці — готові команди invite для тих, хто відвалився.

## 8. Скільки це коштує

Приблизні цифри (серпень 2026, звіряй з https://www.browserbase.com/pricing):

- **Free** — $0: 1 одночасна сесія і ~1 година браузерного часу. Вистачить залогінити авторів і поганяти check кілька днів, не більше. **Проксі у free plan немає** — lifleet це помічає сам (402 від API) і працює без них; мінус: трафік іде з датацентр-IP, LinkedIn частіше показує challenge. На платному плані проксі увімкнуться автоматично, без змін.
- **Платний базовий план** — ~$39/міс: ~100+ годин браузерного часу, кілька одночасних сесій (нам все одно потрібна одна).
- Від чого залежить витрата:
  - **Браузерні хвилини**: `check --all` для 5 авторів ≈ 3–5 хв/день ≈ ~2 год/міс; щоденний робочий прогін додає стільки, скільки триває `do_work` на кожного.
  - **Проксі-трафік**: тарифікується окремо за GB (~$10/GB). LinkedIn-стрічка важка (кілька MB за прогін), тож 5 авторів щодня — порядку 1 GB/міс.
- Разом реалістичний бюджет: **$39–60/міс** на п'ятьох авторів при щоденному прогоні.

## 9. Коли щось зламалось

- **`dead`** — LinkedIn розлогінив (протухли куки). Лікується одним invite:
  `lifleet invite <slug>` → надіслати лінк → автор логіниться → Enter.
- **`challenge`** — LinkedIn просить верифікацію. Спершу автор має зайти в LinkedIn **зі свого телефона** і пройти перевірку (підтвердити «це я»). Коли з телефона все чисто — робиш `lifleet invite <slug>` як звичайно.
- **`429` від Browserbase** — досягнуто ліміт одночасних сесій: десь висить жива сесія. Відкрий дашборд browserbase.com → **Sessions**, знайди сесію зі статусом RUNNING і зупини її (Release/Stop). Потім повтори команду. (lifleet сам релізить свої сесії навіть при Ctrl+C, але сесія могла лишитись від збою мережі чи вбитого процесу.)
- **`error`** — разова мережева проблема або таймаут. Повтори `lifleet check <slug>`; якщо стабільно — дивись сесію в дашборді Browserbase (там видно скріншоти і логи).
- **`unknown`** — LinkedIn показав щось нове. Найшвидша діагностика: `lifleet invite <slug>` і подивись очима, що на екрані (це безпечно — просто не проси автора логінитись, а закрий Ctrl+C… але пам'ятай, що тоді краще самому не тикати в його акаунт — дивись, не дій).

## 10. Приватність — чесно

- **Що гарантовано технічно**: у сесії логіну стоїть `record_session=False` — Browserbase не пише replay, тобто відео/відтворення того, як автор вводив пароль, **не існує ніде**. Пароль і пошта не проходять через цей інструмент: немає жодного поля, файлу чи env-змінної для них. У `authors.json` лежить тільки `context_id` і статуси.
- **Що тримається на довірі**: куки залогіненої сесії зберігаються в Browserbase Context, а доступ до нього дає API-ключ проєкту — і цей ключ у мене. Тобто я не знаю пароль автора, але технічно можу відкрити браузер від його імені. Це і є суть інструменту, але автор має це розуміти — гарантія тут **організаційна**, не технічна.
- **Якщо комусь потрібна тверда гарантія**: заведи для цього автора **окремий проєкт Browserbase** (окремий `BROWSERBASE_PROJECT_ID` + окремий API-ключ), і нехай ключ зберігається в автора — тоді запуск дій від його імені можливий лише коли він сам дає ключ на час прогону. lifleet це підтримує без змін коду: просто інші значення в `.env`.
- Видалення: `lifleet drop <slug>` прибирає автора з реєстру, а сам профіль (context з куками) видаляєш у дашборді Browserbase — після цього доступу не має ніхто.
